# Análise de Gaps (AS-IS vs TO-BE MVP)

Comparação direta entre o estado recuperado em `develop` (`16a8e69`) e os requisitos de produto, segurança, privacidade e operação definidos para o Fit Brother 2.0.

| Domínio / Capacidade | Estado Atual (AS-IS) | Estado Alvo (TO-BE MVP) | Gap Identificado | Prioridade |
| :--- | :--- | :--- | :--- | :--- |
| **Controle de Acesso e Multi-Tenancy** | `POST /students` aberto; sem `trainer_id`; listagem global; `users.id != students.id` | Default-deny, RBAC estrito, vínculo explícito `organizations`/`trainer_student_relationships`, isolamento total entre alunos e treinadores | **Crítico** (risco de violação de dados e quebra funcional para alunos) | P0 (Fase 1 & 3) |
| **Privacidade e LGPD** | CPF obrigatório (`NOT NULL`) e descriptografado em endpoint acessível a qualquer trainer; anonimização incompleta; sem registro de consentimento ou direitos dos titulares | Remoção/descontinuação de CPF obrigatório; minimização; anonimização transacional completa + revogação de sessões; registro de consentimento, solicitações de titularidade e retenção | **Crítico** (conformidade Art. 11 e Art. 18 LGPD) | P0 (Fase 1 & 3) |
| **Autenticação e Sessões Web** | Login/Refresh próprios sem transação; `kid` ausente; Flutter `logout` quebrado; `refresh` stub; tokens em `localStorage` via `flutter_secure_storage` | Sessão segura Web (cookies `HttpOnly; Secure; SameSite` via mesmo domínio/BFF ou estratégia hardening documentada), convites com token único, ativação, reset de senha, MFA opcional/TOTP para trainer | **Alto** | P0/P1 (Fase 1–3) |
| **Biblioteca de Exercícios** | Exercício é texto livre (`name`, `sets`, `reps`) por sessão | Catálogo independente com grupos musculares, equipamentos, categorias, tradução PT-BR e mídias licenciadas (`free-exercise-db` Unlicense + vídeos privados do trainer) | **Alto** | P1 (Fase 4) |
| **Prescrição / Workout Builder** | Criação linear de plano → sessão → exercício sem edição, duplicação ou template | Templates reutilizáveis, duplicação, edição segura, versionamento/publicação preservando histórico executado pelo aluno | **Alto** | P1 (Fase 5) |
| **Experiência do Aluno (Mobile-First)** | **Inexistente** (0 telas, 0 logs de treino) | Navegação inferior (`Início`, `Treinos`, `Histórico`, `Evolução`, `Perfil`), treino do dia, cronômetro de descanso, registro de séries/cargas/reps, feedback e visualização de mídia | **Alto** (sem ele não há produto para aluno) | P1 (Fase 6) |
| **Avaliações Físicas e Evolução** | Apenas tabela `biometric_data` ociosa no banco | Fluxo flexível de medidas (não todas obrigatórias), histórico de peso/medidas/cargas/volume/PRs, gráficos sem diagnósticos clínicos | **Médio/Alto** | P1 (Fase 7) |
| **Dashboard Operacional e UI Premium** | Tela de login, dashboard simples com lista de alunos e formulários crus | Design System próprio (grafite/preto/branco + verde-lima, Light/Dark, WCAG 2.2 AA), layout responsivo Trainer (sidebar desktop/tablet) vs Aluno (bottom nav mobile) | **Médio** | P2 (Fase 8) |
| **Infraestrutura e Saída do GCP** | Dependência de `REDIS_URL` no boot, docs apontando para Cloud Run, sem SMTP | Remoção de Redis obrigatório e do GCP; stack gratuita inicial (Render/Fly/Koyeb + Supabase Postgres + Cloudflare Pages/R2 + Resend/Brevo) com limites e plano de escala | **Alto** | P0/P1 (Fase 2 & 9) |
| **Qualidade, Testes e DevSecOps** | Sem testes de integração DB reais, sem testes de contrato de vídeo, CI sem Flutter/Gitleaks/Semgrep/Trivy/SBOM | Pipeline completa (Go + Flutter + SAST + DAST + SCA + SBOM + Testcontainers/PG real + suíte obrigatória de segurança RED/GREEN) | **Alto** | P0/P1 (Fase 1 & 2) |
